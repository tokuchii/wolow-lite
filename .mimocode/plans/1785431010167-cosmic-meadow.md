# Plan: Wire Up Real App Icons (PC → Phone)

## Problem

The WOLOW Lite backend already extracts real app icons from `.exe` files via Win32 APIs (`actions.py:get_app_icon_png`), and the `/apps/icon` endpoint serves them as PNG. But the Flutter mobile client **never calls this endpoint** — instead, `_AppIcon` renders a colored rectangle with the app's first letter. The user's script adds UWP scanning (Microsoft Store apps) which is also missing from the existing backend. Current icon extraction is 32x32 (Win32 default) — needs upgrading to 256x256 for phone displays.

## Goal

Phone displays the actual Windows app icons extracted from the PC, not placeholder letters. Icons at 256x256 for sharp display on phone screens.

### 1. Backend: Upgrade icon extraction to 256px (`pc_agent/actions.py`)

The current `get_app_icon_png()` (line 842) uses `GetSystemMetrics(SM_CXICON)` which returns 32x32. Replace with `SHGetImageList` + `IImageList` COM interface to extract 256x256 icons from the Windows shell image list.

**Replace the body of `get_app_icon_png()`** with a new implementation that:

1. Calls `ctypes.shell32.SHGetFileInfoW()` with `SHGFI_SYSICONINDEX` to get the icon's index in the system image list
2. Calls `SHGetImageList(SHIL_EXTRALARGE)` (0x2) to get the 48px image list, or `SHIL_JUMBO` (0x4) for 256px
3. Uses `IImageList.GetIcon()` to extract the HICON at full resolution
4. Renders to a 256x256 PIL Image and returns PNG bytes

### 2. Backend: Add UWP app scanning (`pc_agent/actions.py`)

The existing `_scan_windows_apps()` scans Start Menu shortcuts + registry, but misses UWP/Microsoft Store apps. Add a UWP scan using PowerShell `Get-StartApps`.

**In `_scan_windows_apps()`**, after the registry scan block (~line 712), add:

```python
# 3. Scan UWP / Microsoft Store apps via PowerShell
try:
    ps_result = subprocess.run(
        ["powershell", "-Command", "Get-StartApps | ConvertTo-Json"],
        capture_output=True, text=True, timeout=15,
        creationflags=subprocess.CREATE_NO_WINDOW,
    )
    if ps_result.returncode == 0 and ps_result.stdout.strip():
        import json as _json
        data = _json.loads(ps_result.stdout)
        if isinstance(data, dict):
            data = [data]
        for entry in data:
            name = entry.get("Name", "")
            app_id = entry.get("AppID", "")
            if name and app_id and "!" in app_id:
                key = name.lower().strip()
                if key not in found and not _is_bloatware(name):
                    found[key] = {
                        "name": name,
                        "path": app_id,
                        "source": "uwp",
                    }
except Exception:
    pass
```

For UWP icons: UWP apps don't have .exe files to extract from. Their icons live in the app package. Add a helper `_get_uwp_icon_png(app_id)` that:
1. Uses PowerShell to find the app's install path via `Get-AppxPackage`
2. Reads the icon PNG from the package's `Assets/` folder (typically `*.png` files like `Square150x150Logo.png` or `StoreLogo.png`)

### 3. Backend: Return icon URL in `/apps` response (`pc_agent/agent.py`)

Modify the `/apps` endpoint (line 300) to include an `icon_url` field for each app:

```python
@app.route("/apps", methods=["GET"])
@require_token
def apps():
    log.info("Apps request from %s", request.remote_addr)
    result = get_installed_apps()
    # Inject icon_url into each app entry
    base = f"http://{request.host}"
    for a in result.get("apps", []):
        path = a.get("path", "")
        if path:
            a["icon_url"] = f"{base}/apps/icon?path={urllib.parse.quote(path)}"
    return jsonify(result)
```

This requires adding `import urllib.parse` at the top of agent.py.

### 5. Flutter: Update `_AppIcon` to show real icons (`lib/main.dart` ~line 2737)

Replace the `_AppIcon` widget to accept an optional `iconUrl` and display the real icon via `Image.network` with the colored-initial as fallback:

```dart
class _AppIcon extends StatelessWidget {
  final String initial;
  final Color color;
  final double size;
  final double radius;
  final String? iconUrl;  // NEW

  const _AppIcon({
    required this.initial,
    required this.color,
    this.size = 50,
    this.radius = 12,
    this.iconUrl,  // NEW
  });

  @override
  Widget build(BuildContext context) {
    return Container(
      width: size,
      height: size,
      decoration: BoxDecoration(
        borderRadius: BorderRadius.circular(radius),
        boxShadow: [
          BoxShadow(
            color: color.withValues(alpha: 0.25),
            blurRadius: 6,
            offset: const Offset(0, 2),
          ),
        ],
      ),
      clipBehavior: Clip.antiAlias,
      child: iconUrl != null && iconUrl!.isNotEmpty
          ? Image.network(
              iconUrl!,
              fit: BoxFit.cover,
              width: size,
              height: size,
              headers: const {'X-Token': ''},  // token injected via query param in URL
              errorBuilder: (_, __, ___) => _fallback(),
            )
          : _fallback(),
    );
  }

  Widget _fallback() {
    return Container(
      decoration: BoxDecoration(
        gradient: LinearGradient(
          begin: Alignment.topLeft,
          end: Alignment.bottomRight,
          colors: [color, color.withValues(alpha: 0.7)],
        ),
      ),
      child: Center(
        child: Text(
          initial,
          style: TextStyle(
            color: Colors.white,
            fontSize: size * 0.44,
            fontWeight: FontWeight.w700,
          ),
        ),
      ),
    );
  }
}
```

2. **App picker list** (~line 2317): `_AppIcon(initial: initial, color: color, size: 36, radius: 8, iconUrl: app.iconUrl)`
3. **Dashboard device card** pinned apps (~line 2591 area): same pattern

For each, look up the matching `AppEntry` from `_availableApps` and pass its `iconUrl`.

### 7. Backend: Token in icon URL (no header needed)

Since the icon URL is fetched via `Image.network` which doesn't easily support custom headers in all cases, embed the token as a query parameter in the icon URL:

```python
a["icon_url"] = f"{base}/apps/icon?path={urllib.parse.quote(path)}&token={EXPECTED_TOKEN}"
```

The existing `require_token` decorator already checks `request.args.get("token", "")` (line 117 of agent.py), so this works without Flutter changes to headers.
